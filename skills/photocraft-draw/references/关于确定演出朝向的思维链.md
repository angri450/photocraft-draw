# 关于确定演出朝向的思维链

## 关于这一层在流程里的位置

动作状态定的是谁在使什么劲，朝向定的是身体的哪一面给观众看。这是两件事，
不是一个动作的两种说法。

一个人可以往下压，同时侧着身对着对手。也可以正面朝观众把兵器举过头顶。
动作和朝向互相独立，方案里分开写，分开检查。

朝向和动作一起放在写方案之前定。等到位置阶段再补朝向，已经晚了。
关节表一写死，正面和背面在几何上分不出来，那时候再改就要重排整格。

## 关于白模为什么读不出正反面

figure_rig 画的是关节球、骨段和一个头椭圆。正面和背面在几何上完全一样：
肩一样宽，头一样圆，白模里也没有脸。没有脸就没有正反面。

方案里不写朝向，生图模型就自己编。编出来的多半是两个人转身互相砍，
观众看见两个背影。引擎的投影跟这件事没有关系，figure_rig 没有面片，
法线没有地方依附，旋转一个人也不等于让他背对观众。

## 关于方案里怎么写

figure_rig 的 face 参数有四个值。

| 值 | 意思 |
|---|---|
| front | 正面朝观众，胸肩打开 |
| left | 侧身转向画面左侧 |
| right | 侧身转向画面右侧 |
| back | 背对观众 |

写在 figure_rig 组件的 params 里：

```json
{
  "component": "figure_rig",
  "params": {"root": [300, 700], "height": 440, "face": "front"}
}
```

写上 face 以后，白模的头会点上五官。front 画两只眼睛加鼻子加嘴，
left 和 right 把五官往侧面挪并加一个鼻尖，back 只画一道后脑线。
这样白模一眼能看出脸朝哪边，人物姿态定错的时候当场就能看出来。

## 关于这一层查什么

声明的朝向和关节表要对得上。下面五个量能从关节表里量出来。

1. 肩宽占身高的比例。正面朝观众的人两肩要展开，占身高低于 0.18 读作侧身。
2. 头偏出身体中线的距离。头要正对身体中线，高于身高的 0.07 读作扭头或者转身。
3. 颈和躯干的拧角。脖子拧着读作转着身子，高于 15 度报出来。
4. 躯干偏离竖直的角度。正面朝观众的人躯干要立着，高于 20 度读作侧着身子。
5. 两肩的高差。正面朝观众的人两肩一样高，高于身高的 0.04 读作身子转过去了。

大闹天宫续作贴身扭打那一格解出来的一组数可以当参考：
悟空肩宽占身高 24%，头偏出中线 4 像素，颈与躯干拧 2.0 度，
躯干偏离竖直 2.1 度，两肩高差 0 像素。
二郎神肩宽占身高 23%，头偏出中线 2 像素，颈与躯干拧 2.2 度，
躯干偏离竖直 2.2 度，两肩高差 0 像素。
这两个人是正面朝观众的。

## 关于背对观众

项目规矩是禁止背场。face 写成 back，报告里报出来，由作者定夺。
引擎不做硬禁止，因为有的画面确实需要一个人背对镜头。

## 关于没声明朝向的角色

跟动作状态一样，这一层不写不算错，报告里列出哪些角色没声明朝向。
方案里的人物一个都不写，就是全都靠模型自己编。

## 关于朝向要进画面稿

成品插画只由英文稿喂给生图模型，白模不进模型。稿子里不写朝向，
模型就自己编，编出来的多半是两人转身对着打，观众看见两个背影。

引擎会把 face 翻成一句话自动接进画面稿。front 翻成
facing the audience squarely, chest and shoulders open to the viewer,
face fully visible。作者自己写的 describe_en 不要再重复这句话，
接一遍就够。

## 关于命令

```sh
photocraft-draw facing plans/xxx.json
photocraft-draw facing plans/xxx.json --json out/facing.json
```

报告分三段。第一段是每个角色的朝向声明，第二段是量出来的五个数，
第三段是朝向提示。提示为空，说明朝向这一层自洽。

## 关于和白模其他检查的关系

facing 读的是绘制方案，跟 motion 一样，出图之前就能跑。
occlusion 查谁挡谁，contact 查压在哪，depth 查层序和三维坐标。
四者查的是不同的东西，都要跑。

朝向这一层不管位置对不对，也不管动作对不对。
位置查交叉角和手臂长度，动作查意图向量和兵器主轴，
朝向查身体给观众看的这一面。三件事互不替代。
