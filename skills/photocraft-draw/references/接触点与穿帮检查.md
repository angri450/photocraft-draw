# 接触点与穿帮检查

`photocraft-draw contact` 在 `occlusion` 之上再走一步。`occlusion` 只回答「谁压谁、压了多少像素」，看不出「压在哪里」；`contact` 把每一对部件的交叠区拆成一片一片，给出质心坐标、面积和范围，再把方案里的关节坐标对上去，能查出「一件兵器从某只手穿过去了」这类问题。

## 什么时候用这个命令

白模阶段只摆位置关系，以下三个场合都要跑一次。

一、兵器相交的地方。要确认两根兵器真的交叉了，而且上下层次是自己想要的那一层。

二、手握兵器的地方。要确认手压在兵器上，而且兵器没有从手背后穿过去。

三、角色贴着大件物体的地方。要确认角色没有被建筑、云层、栏杆整个盖住。

## 命令怎么写

```sh
photocraft-draw contact out/xxx.psd --plan plans/xxx.json --map out/contact-map.png --json out/contact.json
photocraft-draw contact out/xxx.psd --plan plans/xxx.json --no-base
```

- `psd`：分层文件，必填。命令处理的是分层文件，方案只用来查关节归属。
- `--plan`：绘制方案文件。给了才能查关节归属和穿帮提示。
- `--map`：遮挡显露图的输出路径。
- `--no-base`：显露图不用合成图做底，只画接触区。
- `--json`：结构化结果，方便别的脚本接着处理。
- `--tmp`：临时目录，引擎渲染每层透明图时用。

## 报告有三段

### 第一段是接触点清单

列出每一对部件的交叠，编号和显露图上的圈一一对应。

```
  golden cudgel 压 wukong：3272 像素，占下层 6.5%，4 处
     [22] (342.5, 501.2) 面积 1569 范围 316,480 到 372,523
     [23] (431.7, 471.6) 面积 787 范围 417,456 到 447,489
```

「压」的顺序是从前到后。前面那一层盖住后面那一层。位置写成质心坐标，范围写成矩形的外沿。

### 第二段是关节归属

把方案里 `figure_rig` 的关节坐标换算到画布坐标，再算每个关节被哪些部件压住、压住多少。

```
  wukong hand_r (432, 471)
     前层：wukong gripping hand 100%、golden cudgel 98%、three-pointed blade 67%
```

三层分别是「前层」「后层」和角色自己那一层。前层是盖住手的部件，后层是角色压住的部件。

一层里画了多个角色时，称呼后面会带序号，例如「天将第2个」。

### 第三段是穿帮提示

五条规则，命中就报，没命中就不写。

```
  [夹手] wukong 的 hand_r（432, 471）同时被前面的 wukong gripping hand 100%、golden cudgel 98%、three-pointed blade 67% 共 3 件压住，这一带多半有一件兵器不该穿过这只手
  [疑似穿手] wukong 的 hand_l 与 wukong 的 hand_r 都压在 golden cudgel 上，两点相距 250 像素，占该部件跨度 833 像素的 30%；这一带还压着 three-pointed blade、wukong gripping hand
  [挤在一处] （432, 472）一带挤着 4 个部件：golden cudgel、wukong、wukong gripping hand、three-pointed blade
  [穿头] 天兵列阵第1个 的 头部（150, 492）本层的兵器 长戟（131, 527）盖住 52%
  [遮脸] 天将第1个 的 头部（540, 550）前面 孙悟空 的身体盖住 71%
```

## 显露图怎么读

显露图是把接触关系显出来的图，底图压暗去饱和，接触区用上面那一层的颜色填，质心画圈并标上编号，圈里的编号就是报告第一段的编号。

三处红色实心标记是穿帮提示的位置。

图例在左上角，一层一个颜色标记，层名用方案里的原名。

## 五条提示的判断标准

一、夹手。一只手同时被两件以上「角色前面」的部件压住，每件盖住关节圆盘一半以上。手被几件东西压住，读图的人看不出这只手在握什么。

二、疑似穿手。同一角色的两只手压在同一部件上，两点相距不到该部件跨度的四成。兵器横穿双手，一只手本该抓别的东西。

三、挤在一处。三个以上部件的接触区聚在三十像素以内。最后那一层是底板，占画面四分之一以上的大面积层不参与这条。

四、穿头、穿颈。头部和脖子各算一片保护区：头部是椭圆，横向宽度是完整椭圆的八成六，中心比头关节点高三分之一个半径；脖子是圆盘，半径是身高的百分之四点五。这两片区域被前面的兵器盖住四成以上，或者被兵器从中间横穿，就报穿头、穿颈。兵器在角色自己那一层里但排在身体后面的，同样要查。

五、遮脸、遮颈。另一个角色的身体盖住头部七成以上，或者盖住脖子七成以上，读作脸看不清。这类是构图问题，不是穿帮，报出来供人判断。

角色身后的部件不参与前两条。后面的部件挡不住手，穿帮都出在前面的部件上。

头颈这两条分辨到形状一级：同一层里既有身体又有兵器时，命令会单独把每个形状渲染出来，看清到底是哪一件盖住了头。代价是每个候选形状要渲染一次，一张图多花几秒。

## 白模阶段的停止标准

这三条同时成立就停，美术细节不抠。

一、`verify` 通过。

二、目标接触对有非零像素。用 `contact` 查，想让谁压谁，压上就行。

三、像素方向对。想要前面的那一层确实在前面，报告里的顺序和显露图上的颜色都跟着对。

## 这套检查的限度

一、命令分辨不出「该不该握」。一只手里只压着一件东西的时候，命令认为这是正常的握持。有意为之还是画错了，这一步只能自己判断。

二、兵器和手的层次是人定的。同一个位置压着几件东西，是层次排错了还是画得本来就该这样，报告只给数字。

三、`挤在一处` 只数部件个数，不分辨形状。两根兵器交叉加上一只手，是常见的三件挤在一起。

四、四格连环画这种每格一张图的做法，一格执行一次。不要把四格合到一张分层文件里做检查，遮误会混。

五、头颈保护区按方案里的关节表反算，没给 `--plan` 的文件不查这两条。方案里的姿态和实际画出来的不一样，区域会算偏。

六、遮脸这条只分辨层，看不清是哪个角色的哪一段身体。报告只给层名。
