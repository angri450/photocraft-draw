# 四格连环画白模做法

以「大闹天宫」四格为例：独闯南天门、打退天将、斗二郎神、掀凌霄殿。每格 900 乘 1200，暮色调，最后拼成 3600 乘 1200 的长条。

完整生成器在 `D:\agent2\comic\build.py`，一份文件写方案、跑 `verify`、跑 `draw`、跑 `occlusion`、跑 `brief`、拼长条，改参数重跑。这份文件只写关键做法和容易想错的地方。

## 关于每一格的层次

四格都用同一个结构：四个图层加底色，从后到前依次是环境、对手、主角、前景。

| 格 | 环境 | 对手 | 主角 | 前景 |
|---|---|---|---|---|
| 一 | 南天门 | 天兵列阵 | 孙悟空 | 前景云阶 |
| 二 | 天宫广场 | 天将 | 孙悟空 | 前景碎石 |
| 三 | 云海 | 二郎神 | 孙悟空 | 哮天犬 |
| 四 | 凌霄殿 | 殿上百官 | 孙悟空 | 碎瓦 |

主角永远压在对手前面，前景永远压在主角前面，四格读起来才是同一个人的视角。

## 关于兵器握在手里

兵器用 `custom_shape` 画，手的位置由兵器反算，不要手动画完再凑。

四步。一、从姿态表里取 `hand_l` 和 `hand_r` 的绝对坐标。二、连成一条直线，方向就是兵器轴线。三、沿这条轴线向两端延伸，得到兵器两端。四、兵器上再添箍带、刃头这类附件。

这样兵器自动握在两只手上，改姿态时兵器跟着走。

```python
def joints(pose, root, height):
    ox, oy = root
    return {name: (ox + x * height, oy + y * height) for name, (x, y) in pose.items()}


def rod(p1, p2, ext1, ext2, width):
    dx, dy = p2[0] - p1[0], p2[1] - p1[1]
    length = math.hypot(dx, dy) or 1.0
    ux, uy = dx / length, dy / length
    a = (p1[0] - ux * ext1, p1[1] - uy * ext1)
    b = (p2[0] + ux * ext2, p2[1] + uy * ext2)
    nx, ny = -uy * width / 2, ux * width / 2
    return [[a[0] + nx, a[1] + ny], [b[0] + nx, b[1] + ny],
            [b[0] - nx, b[1] - ny], [a[0] - nx, a[1] - ny]]
```

## 关于两件兵器真正相交

「相交」不是两个形状挨着，是两件兵器在同一个点上交叉，而且那个点在画心上。

做法是反过来算，不是一个一个凑位置。

一、先定主角的兵器。孙悟空的金箍棒从 `hand_l` 到 `hand_r` 连线再向两端延伸，得到一条直线和棒身长度。

二、在棒身上选一个目标点，比例取 0.5 到 0.7。0.5 偏内，0.7 偏外。

三、给对手的刃定一个方向，一般斜指左上，方向向量取负 x 负 y。

四、反推对手握兵器的位置：目标点减去方向乘以刃长，就是对手的手应该在的地方。

五、再从对手的手反推对手的站位：`root` 等于手的位置减去关节表里手相对髋部的偏移。

```python
target = (a[0] + (b[0] - a[0]) * 0.65, a[1] + (b[1] - a[1]) * 0.65)
ux, uy = -0.34, -0.94
grip = (target[0] - ux * 130, target[1] - uy * 130)
root = (grip[0] + 0.42 * height, grip[1] + 0.50 * height)
```

这么算完，刃尖正好对在棒身指定的位置上，两件兵器形成十字。跑完 `occlusion` 能看到主角挡住对手的比例从百分之二涨到百分之四，这个数就是交叉是否成立的证据。

## 关于四格各自的动作

一、独闯南天门。主角双手举棒过顶，棒斜着从左下到右上。天兵分前后两层排门前，每层左右各一人，中间留出通道。

二、打退天将。主角在画面左侧横扫金箍棒，棒从左上往右下压过去。三名天将躯干往后仰，脚线一高一低错开，不要站成一条直线。地面上画几道地砖线，地面才不空。

三、斗二郎神。主角在左举棒斜架，对手在右双手持三尖两刃兵器，刃口斜指左上，两件兵器在画心相交。哮天犬从右下扑进，压住两人下半身。

四、掀凌霄殿。主角腾空举棒砸向殿顶，双腿张开，脚不着地。三名百官在殿前惊散举手，分散在主角两侧，别让主角挡住中间那个。碎瓦压在最前。

## 关于返工时先看哪里

这一轮下来，四格最容易出问题的地方是这些。

1. 屋顶。开始画成了人字大帐篷，加了平正脊、凹曲坡面、檐口起翘、翼角、鸱吻、檐下柱列才像建筑。
2. 兽类剪影。开始是一条 blob 加四条放射状的腿，像蜘蛛。改成身体一条闭合轮廓、前后两组腿各自朝不同方向伸、耳朵和尾巴独立之后才认出是犬。
3. 兵器相交。开始是棒头和刃尖几乎挤在同一点，看着像重叠不像交叉。按上面的反算法算完才成立。
4. 人物站位。开始六个人站在同一条水平线上，改成前后两层、错开高度才有纵深。
5. 天上掉下的碎瓦。开始是几个方片浮在空中，改成不规则瓦片加一条垂边才像在掉的瓦。

## 关于遮挡数字怎么读

`occlusion` 输出的格式是「上面挡住下面：像素数，占下层百分之几」。这个百分比是相对被挡那一层的面积，不是相对整个画面。主角挡住对手百分之四点二，意思是主角有百分之四点二的面积压在对手身上。

层与层之间的数字加起来不会超过一百，超过一百说明两层之间有互相压住，这在画家算法里不会发生，出现了就查图层顺序。

## 关于接触点和穿帮检查

`occlusion` 只说谁压谁，看不出压在哪里，也查不出兵器从手背后穿过去。白模阶段再跑一条 `contact`：

```sh
photocraft-draw contact out/panel3.psd --plan plans/panel3.json --map out/panel3-map.png
```

兵器单独成层，画在角色层前面。路径蹭到手的关节圆盘，手就被盖住，看上去像握着，其实手在兵器后面。`contact` 的「夹手」和「疑似穿手」两条提示查的就是这个。

四格跑完 `contact`，穿帮提示是空的，说明兵器和手的层次都对。提示会写清楚是哪一件兵器、哪一个关节、压住百分之几，接触点清单给出每一处交叠的坐标和范围，显露图把这些位置用颜色显出来。详细读法见 [接触点与穿帮检查](接触点与穿帮检查.md)。

## 关于自己的核对

每格改完先跑 `verify`，确认部件没有出画。再跑 `occlusion`，看主角挡住对手的比例，对手被挡的比例上去了，说明两件兵器真的交叉上。再跑 `contact`，接触点清单看兵器交叉在哪，关节归属看手压在什么上，穿帮提示要为空。

`verify` 只保证结构合法，画面好不好看要自己看 PNG。遮挡比例的数字只说明关系成立，说明不了动作好看。
