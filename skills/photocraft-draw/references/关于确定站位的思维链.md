# 关于确定站位的思维链

## 关于这一层在流程里的位置

遮挡关系定的是谁挡住谁。动作状态定的是谁在使什么劲。朝向定的是身体给观众看的这一面。站位定的是这几个人站在画面的哪一块，谁在前，谁在后，谁腾空，谁站在地上。

这四件事是并列的，不是一件事的先后步骤。动作定下来，站位才有东西可摆；站位摆出来，朝向和遮挡才有依据。顺序倒过来做，每一步都会被前面那一步锁死。

## 关于动作怎么定站位

三件事由动作直接推出来。

一、谁腾空，谁站在地上。往上打的那个人脚下没有支点；往下压的那个人踩在地上，靠腰腿使劲。同一格里一个人既腾空又站着，读出来是扎马步，不是打斗。

二、谁在前，谁在后。蓄力的人离观众近一些，抢先出手的人离观众远还是近，看这一格画的是动作的哪一刻。前后差一层，在白模上就是差一个 depth。

三、谁占画面哪一块。横向分左中右三格，纵向分头顶、胸口、脚底三段，身高占画幅多少比例。人物占在哪一格，是站位算出来的结果。

这三条在方案里都能写成数字。引擎的 `views` 会把横向三格、头顶纵向三格、身高占画幅比例、离地像素、两人高低差算出来，写进画面稿。

## 关于背场要有理由

项目规矩禁止背场。一个人把后脑勺对着观众，画面读成他要走或者要逃，正面发生的冲突就断了。

真要背场，理由得写下来。三种理由站得住。

一、他正在躲。对方的东西正冲着他来，他侧身让开，这时候背身有道理。

二、他在抢位置。他要抢一个只有背对镜头才能抢到的位置，比如从柱子后面绕过去。

三、他正往外走。动作朝画面外，跑或者退。

写不出理由，就换朝向，或者把动作改掉。改动作比解释省事。

## 关于空着的手必须有来由

一只空着的手在画面里是一句话。常见四种来由。

一、扶着别的东西。墙、柱子、兵器、另一个人的肩。

二、撑住地面。站在地上的人单手撑地，撑地那条手臂要直，手掌要摊平。

三、护住要害。手臂拢在胸前或者腹前，手握成拳。

四、甩出去找平衡。人在被甩或者在翻滚，这只手会离开身体。

垂着的手、张开的手、举在半空不知道干什么的手，没有来由，读出来的是犹豫或者摆姿势。

写关节表的时候，每一只手都要能答出这个问题：它握着什么，或者它在撑什么。答不上来就是漏了。

## 关于两个深度不能混

`depth` 是遮挡顺序，`z` 是空间深度。这是两根轴。

`depth` 决定谁压谁，在白模上直接生效。`z` 决定这个部件在空间里离观众多远，只在三视图和画面稿里生效。

一根棒在画面上被二郎神的腿挡住，这是 `depth` 定的，在白模上就该这样画。它在空间上仍然可以处在二郎神身体的前面，因为 `z` 单独写着。层上可以写 `z`，关节表里的点也可以写第三个数字 `z`，人物的关节深度等于层深度加自身深度。

分开建模的好处是，作者可以既要「悟空的手画在棒上头」，又要「棒真的在悟空手的高度上」。这两件事在平面白模上互斥，在空间里不矛盾。

## 关于命令怎么写

```sh
photocraft-draw views plans/xxx.json --out-dir out --unit 40 --json out/views.json
```

报告四段：人物站位、兵器深度、兵器交叉、站位提示。

三视图的读法和坑见 [三视图的用法与坑](三视图的用法与坑.md)。
