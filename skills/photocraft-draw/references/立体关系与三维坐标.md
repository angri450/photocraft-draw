# 立体关系与三维坐标

`photocraft-draw depth` 把分层文件的层序翻译成深度表和三维坐标。

`occlusion` 和 `contact` 都在二维层面交代事情：谁压谁、压在哪里。`depth` 补上第三维，让「这一层离观众多远」和「这个部件在空间里的位置」有数字可查。

## 什么时候用这个命令

一、想知道整张图的空间结构。报告给出层深表，一层一个 z 值。

二、调 xy 坐标之前，先看清现有的前后关系。`depth` 报出每层的三维坐标，把坐标按同一套斜度重新投影一次，位置和原图一致，可以拿来核对。

三、决定某个部件该往前挪还是往后挪。相邻两层的深度差会报出画面上错开多少像素，往前挪一层要跟着挪多少，一眼能算出来。

## 命令怎么写

```sh
photocraft-draw depth out/xxx.psd
photocraft-draw depth out/xxx.psd --json out/depth.json
photocraft-draw depth out/xxx.psd --plan plans/xxx.json
photocraft-draw depth out/xxx.psd --unit 2 --skew-x 0.6 --skew-y 0.3
```

- `psd`：分层文件，必填。
- `--plan`：绘制方案文件。给了就用方案里声明的 `depth` 算 z，末尾多一段对照表。
- `--unit`：每层深度差，默认 1.0。层数多的时候调大，层数少的时候调小。
- `--skew-x`：深度到横向偏移，默认 0.45。
- `--skew-y`：深度到纵向偏移，默认 0.28。
- `--ref-width`：参考画布宽度，默认跟画布同宽。
- `--json`：结构化结果。

两个 skew 的默认值跟引擎的三维组件一致，改了这两个值，报出来的坐标就不能直接跟引擎里画的三维盒子对上了。

## 方案里的 depth 字段

绘制方案的每一层可以写 `depth`，数字越大离观众越远，跟 z 一个方向。

```json
{
  "layers": [
    {"name": "南天门", "depth": 3, "components": []},
    {"name": "天兵列阵", "depth": 2, "components": []},
    {"name": "孙悟空", "depth": 1, "components": []},
    {"name": "前景云阶", "depth": 0, "components": []}
  ]
}
```

三件事要知道：

一、`depth` 接管层序。写了 `depth` 的方案，画的时候按 `depth` 从大到小画，数组顺序不起作用。同一份方案把数组顺序倒过来，画出来完全一样。

二、`depth` 要么每层都写，要么都不写。混着写会被校验拦下来，提示哪几层没写。

三、`depth` 相同时按数组顺序分先后。

`depth` 的好处是把远近关系写成数字，方便推理：哪一层在前、哪一层在后，一眼能算，也不用数数组下标。

不带 `--plan` 时，z 按成品层序推，每层差 1，`--unit` 定这个差的尺度。带 `--plan` 时，z 直接取方案声明的 `depth`，`--unit` 只作倍率。

## z 值怎么定

z 越大离观众越远，跟引擎里 `box3d_scene`、`rider3d` 两个组件一致。

层序里越靠前的层 z 越小。引擎的 `info` 输出把层按从前到后排，所以索引 0 那一层 z 最小，画在最后面。

## 报告三段

### 第一段是层深表

从后到前排，一层一个 z 值，带范围和三维坐标。

```
  z  3.00  wukong                     范围 137,429 到 414,1086  三维坐标 (274.65, 758.84, 3.0)
  z  2.00  erlang shen                范围 490,425 到 765,1067  三维坐标 (627.1, 747.06, 2.0)
  z  1.00  hound                      范围 327,892 到 630,1032  三维坐标 (478.55, 962.78, 1.0)
```

三维坐标是部件中心的反算值。反算的规矩是：投影时横向偏移 z 乘 skew_x，纵向偏移 z 乘 skew_y，把这个偏移减掉就得到世界坐标。

### 第二段是相邻两层的深度差

每两层之间差多少层，同一个世界坐标在画面上错开多少像素。

```
  wukong 比 three-pointed blade 近 1.00 层，同一世界坐标下 three-pointed blade 在画面上偏右 0.45、偏上 0.28，单位画布像素
```

这一段是调坐标时最常用的数字。想把某个部件往前挪一层，画面上跟着挪多少，查这一行就行。

### 第三段是每个部件的三维坐标

按层内的形状拆开，每一个形状给一个坐标。同一层里的子部件和所在层同深度。

### 第四段是方案声明和成品层序的对照

带了 `--plan` 才有这一段，逐层核对方案写的 `depth` 和成品实际的 z。

```
  前景云阶                       声明 depth  0.00，成品 z  0.00
  孙悟空                        声明 depth  1.00，成品 z  1.00
  南天门                        声明 depth  3.00，成品 z  3.00
  底色                         方案里没有这一层，z 按前后位置算 4.00
  方案声明和成品层序一致
```

底色和文字层不在方案里，z 按前后邻居插值。方案和成品对不上时，这一段会点出哪一层声明更远却压在前面。

## 三维坐标怎么反算

引擎的三维组件投影时这样算：

```
px = x + z * skew_x
py = y - z * skew_y
```

反过来，从画面坐标反推世界坐标：

```
x = px - z * skew_x
y = py + z * skew_y
```

z 越大离观众越远，同一个世界坐标在画面上越偏右上。

## 这套计算的限度

一、z 是层序或者方案声明推出来的，不是画出来的。层序只说明谁压谁，具体差多少层是人定的。方案写了 `depth` 时按声明值算，`--unit` 是这个值的倍率；没写时按层序每层差 1，`--unit` 是每层的差值。

二、三维坐标是部件中心的值，一个部件内部的深度差别算不出来。兵器从手边穿到另一边这种情形，坐标读不出来，得查 `contact` 的接触区。

三、坐标的单位是参考像素。`--ref-width` 和画布宽不同时两者按比例换算，报的错开量已经换算成画布像素。

四、底色层也参与编号，占着一个 z 值。它铺满画布，看不出深度信息，读表的时候跳过。
