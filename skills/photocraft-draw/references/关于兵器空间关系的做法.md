# 关于兵器空间关系的做法

## 为什么不能靠看图

白模是投影画出来的，投影把深度扔掉了。兵器在纸面上离胳膊五个像素，可能是从胳膊前面扫过去，也可能是从胳膊和兵器中间穿过去。这两种在白模上长得一样，看图判断经常看错。

看截图放大只能给出印象，给不出数字。空间关系靠线段算：把兵器和四肢都近似成一根线段，取两端坐标，算出两条线段的方程，再算它们之间的距离、相不相交、谁在谁的前面。

这一层引擎做成了常设检查，方案写完就跑一遍，不用靠眼睛盯着白模看。

## relations 命令算什么

```sh
photocraft-draw relations plans/xxx.json --json out/relations.json
```

算出来的东西有四样。

一、两条线段在空间里的最近距离。

二、两条线段在画面上是不是真的交叉，交点在两段上的百分之几。

三、兵器离每个骨段最近多少像素，最近的那一点上前后差多少像素。

四、兵器有没有从另一件兵器和持械者的胳膊之间的那个缝里穿过去。

报告分三段：交叉、距离和看过的几处。结构化结果里的 `issues` 是要改的地方，`notes` 是核对过没问题的重叠。

## 关于那个缝怎么算

缝张开在兵器和手相接的那个点上，两条边是胳膊和兵器。

兵器落在这个角里，要同时满足两条。

一、兵器有一段真的落在那个角里。角是画面上的角，余量三度半，兵器正好压在边上不算，兵器在边上交叉跟穿进缝里是两件事。

二、兵器在那一点的深度卡在兵器和胳膊中间。兵器比两者都靠前，是从人物身前扫过去；比两者都靠后，是从人物身后过去。这两种都不算穿进缝里。

缝的范围从手边到胳膊肘。肘子往后胳膊已经拐弯，那里没有缝。

## 三种重叠要分清

一、挨得太近。兵器和胳膊在画面上靠在一起，深度也差不多。读出来是叠在一起，分不清谁压谁。这是错，要改。

二、从身前扫过去。兵器在画面上压着胳膊，深度差三十像素以上。读出来是兵器从人物身前挥过去，这是对的。

三、从身后过去。兵器在胳膊后头。读出来是兵器从人物身后过去，这也是对的。

## 一件兵器不是一个深度

一件兵器从头到尾常常不是一个深度。棒尾甩在人的身后，棒头压在对手身前，中间擦着身体过去。一层画不出这种前后关系，方案里一件兵器要拆成几段，每段一个深度。

写法是这样。

```json
{
  "name": "golden cudgel",
  "holder": "wukong",
  "axis": [[309, 375], [630, 764]],
  "segments": [
    {"from": 0.0, "to": 0.40, "depth": 5.0, "z": 80, "name": "棒尾"},
    {"from": 0.40, "to": 0.91, "depth": 2.0, "z": -40, "name": "棒身"},
    {"from": 0.91, "to": 1.0, "depth": 1.5, "z": -60, "name": "棒头"}
  ],
  "components": []
}
```

六件事要知道。

一、`from` 和 `to` 是主轴上的位置比例，零是尾端，一是头端。

二、`axis` 写主轴的两端。不写就从控制点里找距离最远的一对。

三、每一段自己的 `depth` 和 `z`。多边形按主轴垂直的方向分开，每一段单独占一层，前后的遮挡由这一段的深度定。

四、段和段要接上，上一段的 `to` 跟下一段的 `from` 一样，校验会拦下接不上的写法。

五、分了段的兵器，整体深度按第一段算，引擎不再拿持械者的手改写，手压在兵器上的做法要靠分层安排。

六、每段的位置比例由模型算，不要手填。金箍棒的第一段到持械者握棒的那只手往后一点，他的手才压得住棒；第二段到棒头进对手身板的地方，那一段才开始压在对手身前。

## 关于 depth 和 z 的换算

层上写 `z` 就能定前后，`depth` 由 `z` 推出来。换算基准从写了 `depth` 和 `z` 的层里取，两个锚点定出一档深度相当于多少像素。只有一个锚点就按引擎默认的四十像素一档。

层上两个都写，引擎核对两件事。远近顺序对不上会报出来，深度和物理深度打架。换算不是同一条直线也报出来，报的是哪一层差多少档。

z 越大离观众更远，跟引擎里 `depth` 命令那套记号一致。

## 兵器深度取哪一层

兵器没有自己的层深度时，取持械者的手。手在哪，兵器就在哪，「手握着兵器」在空间上才自洽。

兵器分了段，就按段自己的 `z` 算，段和段之间可以差很深。一根棒从一个人的身后甩到另一个人的身前，中间的深度差能有一百多像素，这时候它该分段写。

## 报告怎么读

先看空间提示。提示里写「挨得太近」的，把兵器和胳膊在画面上分开一点，或者把深度拉开三十像素以上。提示里写「缝里穿过去」的，把兵器从那个角里挪开，或者把深度挪到兵器和胳膊的前后次序上。

再看看过的几处。这里写的是兵器从胳膊前面或者后面扫过去，前后的关系读得出来，画面上重叠是对的。

最后看交叉那一段。两件兵器的深度差二十四像素以内才算碰得到，差得多说明兵器之间还隔着距离，画面上交叉是假的。

## 命令怎么写

```sh
photocraft-draw relations plans/xxx.json
photocraft-draw relations plans/xxx.json --unit 40 --json out/relations.json
```

`--unit` 是图层 depth 每差 1 相当于多少像素，默认 40。

`--json` 出结构化结果，画面稿里的兵器位置句可以从这份结果来。

## 什么时候用

一、写完方案先跑一遍，别等出图。兵器和肢体在空间上挨得太近，出图模型会自己编一个穿帮的姿势。

二、兵器和对手贴得近的时候。贴身扭打的画法里，兵器多半要在对手身前扫过去，深度写在兵器那一段上，不要指望层序排出来。

三、兵器从人身上压过去的时候。棒头压在对手大腿上，棒身从对手胳膊前面过，两段深度不一样才做得到。
