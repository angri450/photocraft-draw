# 配色检查的改造记录

2026-11-09 改的。这一篇记的是改了什么、为什么改、改完什么效果。
机制怎么用见 [配色检查的判据与分组机制](color-rules.md)。

## 起因

`colors` 检查相邻部件的颜色冲突，但自带样例里三十二份有二十五份过不了。
查下来有三层原因，分开处理。

## 一、分组规则覆盖不了中文命名

`_group` 原来只剥阿拉伯数字尾缀，中文数字不管。
于是「手一」和「手二」成了两组，同一双手被当成相邻部件报冲突。
自带样例全是中文命名，栽在这里。

改成从名字尾部往回剥：方位部位词、紧贴主体的编号、复合编号各有各的算法。
中间用空格隔开的编号留着，那是实例号，「山 1」和「山 2」是两座山。

分组规则从 colorize.py 和 autoshade.py 各一份抽到 grouping.py，两边共用一份。

## 二、判据用包围盒，误报太多

包围盒相交就算挨着。天空横贯整个画布，包围盒和任何东西都相交，
可它跟草坡之间隔着两层山和一条河。

改成按形状本身判断。绘制指令里存着完整的路径，
把贝塞尔曲线离散成多边形，算两个形状有没有真的交叠。
新模块 geometry.py。

按像素渲染也验过一遍，准但慢：三十九个部件要渲染三十九次，
三百九十个部件的样例要跑两分多钟。几何判定快九十倍。

## 三、同一个物体的部件没地方声明

中文没有词边界，「石影 1」和「石底 1」是不是同一块石头，名字讲不清。
靠字符串规则猜不出来。

给 Pen 加了两种声明：

- `pen.group("名字")` 显式指定组名
- `pen.group_by("前缀")` 按主体词归组，同类物件的各个实例归成一组

方案层也能写 `group` 和 `group_by` 参数。
组件代码里声明最准，因为只有组件知道哪些部件属于同一个东西。

## 四、四层豁免

同一个物体的部件颜色接近是正常的，不该报冲突。四层豁免，从松到紧：

1. 同一个组。方案里写 group，或组件里用 pen.group 声明
2. 同一层。一层里的部件是同一片东西的不同部分
3. 声明过豁免的层之间。方案里给层写 exempt，
   远山要融进天空，是同一片景的两部分
4. 跨组件的同类物件。石头散在 rocky_ground 和 foreground_rocks 两个组件里，
   前后的石头是同一类东西

豁免判断在 colorize.exempt_pair，两种检查模式共用一份。

## 配套加的东西

- `check` 命令合并配色检查。方案的总闸不该放过配色问题。
- `colors --fix` 配色求解器，分局部修复和全局优化两种。
  局部修复只动真正撞色的地方，比全局优化快得多，也保住原来的画面。
- `colors --apply` 把算出来的配色写回方案文件。
- `colors --pixel` 按形状判断相邻，不看包围盒。
- `palette.shade` 和 `palette.shade_by`，同色相里调明度。
- 雪山按远近递进明度，跨层也接着递。

## 效果

自带样例的配色检查通过数：

| 阶段 | 包围盒判据 | 几何判据 |
|---|---|---|
| 改之前 | 7 份 | 7 份 |
| 改之后 | 18 份 | 21 份 |

剩下的十一份是真冲突：地面和胶囊马同色、陶瓶和果子太近、山和山明度撞。
这些要逐份重新设计配色，不是工具能自动解的。

测试从五百七十一份增到六百零六份。新增的三十五份守着
分组规则、几何判据、层豁免和状态措辞。

## 顺手修掉的

- `brief` 的英文稿把最前面那层的描述抄了两遍，重复的那句只留层名。
  英文稿从一千八百七十九字降到一千四百五十四字。
- 状态措辞从「通过」改成「检查通过」和「检查未通过」。
  「不通过」里含「通过」两个字，拿输出做子串匹配的脚本会判反。
- `colors` 的 `--gap` 默认值是 0.08，和函数里的 0.12 对不上。
- `colorize.py` 末尾多个引号，模块导入不了，pytest 全绿也没发现。
  现在加了一条守卫测试，每个模块都 import 一遍。
